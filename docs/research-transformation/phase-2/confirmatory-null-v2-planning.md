# Phase 2 replacement confirmatory-null planning

Date: 1 September 2026  
Status: positive-sensitivity and KGW bias-development screens failed; protocol remains a non-executable draft

## Current recommendation

Keep the pinned SmolLM2-135M-Instruct model and replace the capacity-limited Dolly
prompt source with a pinned UltraChat 200k source. This preserves model continuity
while giving the replacement study enough genuinely fresh prompts.

The draft scientific claim remains at most 1% false positives in every one of 60
scheme × key × length cells, with 95% Bonferroni-controlled familywise confidence.
Do not launch the proposed 20,000-per-split design: its 0.5% calibration design
margin failed the positive-sensitivity screen, and subsequent fresh KGW
generation-bias development found no candidate satisfying both detection and
quality guardrails.

A subsequent formal feasibility decision retains canonical KGW for one final,
bounded, preregistered joint gamma-by-delta development study. It does not
authorize generation or make this v2 null draft executable. See
`kgw-feasibility-design-decision.md`.

This is a planning recommendation, not authorization to generate. The draft is
`configs/phase2-confirmatory-null-v2-draft.json`.

- The pinned dataset card identifies the data as English and MIT-licensed.

## Statistical design check

For 20,000 observations per cell, 60 cells, and per-cell alpha `0.05 / 60`:

| Stage | Target upper bound | Maximum strict exceedances | Bound at maximum | Bound at next count |
|---|---:|---:|---:|---:|
| Calibration design | 0.5% | 69 | 0.4961% | 0.5020% |
| One-shot confirmation | 1.0% | 156 | 0.9958% | 1.0014% |

If every cell's true rate is 0.5%, the conservative union-bound probability that
all 60 confirmation cells pass is about 99.9995%. A true rate near 0.603% is the
largest compatible with approximately 95% conservative whole-family pass power.
These calculations validate the proposed margin; they do not show that the future
watermarked-positive detection sensitivity is acceptable.

## Positive-sensitivity result

The completed development screen generated 1,000 fresh watermarked outputs in 200
atomic batches over 2.29 hours. It used 50 outputs for every matched scheme × key
condition and paired 128-, 256- and 512-token prefixes. All 60 compact/native audit
comparisons passed exactly, and no v1 confirmation score was loaded.

The fixed screen required at least 40 detections out of 50 in every cell. Fifty-five
of 60 cells passed. The five failures were all canonical KGW:

| Key | Prefix length | Detections | Rate |
|---|---:|---:|---:|
| kgw-03 | 128 | 38/50 | 76% |
| kgw-05 | 128 | 34/50 | 68% |
| kgw-07 | 128 | 35/50 | 70% |
| kgw-08 | 128 | 31/50 | 62% |
| kgw-08 | 256 | 38/50 | 76% |

Every SynthID cell and every 512-token KGW cell passed. A post-screen planning grid
from 0.5% to 0.8% found no null design margin that both cleared all positive cells
and retained at least 95% conservative 60-cell confirmation power. The grid is
exploratory and cannot independently validate a changed margin.

## Scientific consequence of changing prompt source

The replacement result will apply to the frozen eligible UltraChat `train_sft`
prompt population, not to the former balanced Dolly task-category mixture.
UltraChat is a filtered collection derived from dialogues generated by ChatGPT.
There is no Dolly-style category field, so category-specific claims or tuning are
not part of the proposed protocol.

Changing the prompt source does not change the text-generation model, canonical
KGW/SynthID adapters, keys, lengths, decoder settings, scoring code, or 60-cell
familywise claim. Changing the model to Qwen would require a separate calibration
and confirmation study for that model; Qwen is therefore reserved for later
replication.

## KGW bias-development result

Two completed fresh targeted brackets evaluated canonical KGW keys 03, 05, 07 and
08 at 128 and 256 tokens. Each cell contained 50 outputs and required at least 40
strict detections. Candidate quality was compared with a paired bias-2.0 control
using fixed NLL, repeated-4-gram and distinct-2-gram tolerances.

The first bracket found that 2.5 cleared all detection cells but failed quality in
two; 3.0 failed quality in all eight. The final bounded 2.3/2.4/2.45 bracket also
selected no bias: 2.3 and 2.4 cleared detection but each failed quality in four
cells, while 2.45 failed one detection and three quality cells. Bias-only tuning is
therefore closed. See `kgw-bias-development-report.md`.

## Runtime and storage

The completed 5,000-prompt confirmation split took 4.94 wall-clock hours and used
232 MB. At the same observed rate, one 20,000-prompt split is approximately 19.8
hours and 0.93 GB; both splits are approximately 39.5 hours and 1.86 GB. The local
source and audit cache currently uses about 0.89 GB.

These are linear estimates. Thermal throttling, interruption, and other laptop
load can increase wall-clock time. Atomic five-prompt batches remain the intended
recovery unit.

A local M4 Pro benchmark found that clean generation is about 15% faster on MPS,
but the small sequential keyed scoring operations are about 4.3 times slower there.
Moving the complete pipeline to MPS would increase the estimate to roughly 52
hours. A not-yet-implemented hybrid path using MPS generation and CPU scoring is
estimated at 34-35 hours, about five hours faster than CPU-only. It requires parity,
resume and determinism validation before it can be frozen in a new protocol. See
`apple-m4-pro-device-benchmark.md`.

## Required order before generation

1. Prepare, fingerprint and approve the executable protocol for the fixed joint
   KGW parameter-family study in `kgw-feasibility-design-decision.md`. Do not
   generate before it is frozen; bias-only tuning is closed.
2. Run only that preregistered study with fresh development data and fixed
   detection/quality/stop guardrails.
3. Run an independent fresh all-key positive validation only if that new study
   selects a qualifying parameter set.
4. Reconfirm the scientific claim, including all ten keys and 128 tokens, before
   approving the approximately 40-hour CPU and 1.86-GB result budget.
5. Freeze new disjoint prompt manifests and a final v2 protocol with hashes.
6. Run calibration, fit thresholds once, then run untouched one-shot confirmation.
7. Start attacks only if all 60 v2 confirmation cells pass.

Until steps 1-5 are complete, replacement null generation remains prohibited.
